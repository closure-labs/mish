# Mish 0.1.0-alpha

**Initial alpha — draft, software-qualified; physical event use unqualified.**

Mish is an owner-operated local coordinator for community Meshtastic
participation and private staff/department coordination. This candidate has
never been deployed. Keep the release a draft while physical M2–M5 acceptance
remains open; it is not a production or event-ready release.

## Included

- Rust-native coordinator with authenticated text messaging, alerts with a
  responder/expiry, and explicit browser or radio-reported acknowledgements.
  SQLite acceptance, queue state, radio submission and human response remain
  separate.
- Existing community-channel import or named mesh generation, full 256-bit
  generated keys, scoped community/staff/department QR exports and explicit USB
  provisioning with verified readback.
- Local HTTPS, enrollment/revocation, retention/wipe and backup/fresh-state
  restore that quarantines uncertain snapshot sends instead of replaying them.
- NixOS 26.05 builds composed through Den, operating documentation and
  revision-specific image manifests/checksums.

Community participants send messages through the Meshtastic app. The public
browser provides community enrollment QR codes only. Staff browser reads and
writes require authentication and channel membership. Public QRs intentionally
share the community key and allow transmission; private keys stay in scoped
exports. Web revocation does not revoke a copied radio key.

## Choose the artifact

| Artifact | Purpose |
|---|---|
| x86 QEMU appliance closure | Development and VM evaluation; not a flashable physical disk image |
| x86 installer ISO | Explicit physical installation/rescue tooling; does not automatically partition or erase a disk |
| Pi 4 ARM SD image | Pi 4 qualification target; physical boot, firmware, USB and commissioning remain unverified |

Download the artifact, its architecture-specific `SHA256SUMS`, build manifest,
source revision and operating documentation from the same release candidate.
Verify the supplied checksums before using the media and retain its source
identity with the acceptance record. The tagged workflow must rerun required
checks and realize these artifacts from the tag; earlier build evidence does
not replace that candidate's manifest or checksums.

Start with [commissioning and recovery](https://github.com/closure-labs/mish/blob/v0.1.0-alpha/docs/commissioning.md), then follow
[channel enrollment](https://github.com/closure-labs/mish/blob/v0.1.0-alpha/docs/channel-enrollment.md). Prepare required build inputs
before entering an offline venue. Use the [operator runbook](https://github.com/closure-labs/mish/blob/v0.1.0-alpha/docs/operator-runbook.md)
and complete the [physical acceptance record](https://github.com/closure-labs/mish/blob/v0.1.0-alpha/docs/acceptance.md) on named hardware.

## Evidence and remaining gates

The development evidence records 68 Rust behavioral tests, seven browser
channel-selection tests, native x86/ARM software qualification and x86 VM
integration. [Den software checks](https://github.com/closure-labs/mish/actions/runs/38189634053),
[image qualification](https://github.com/closure-labs/mish/actions/runs/38189631186)
and [merge-group qualification](https://github.com/closure-labs/mish/actions/runs/38190366390)
passed for the composition work delivered in PR #20. See
[product status](https://github.com/closure-labs/mish/blob/v0.1.0-alpha/docs/product-status.md) and the
[verification record](https://github.com/closure-labs/mish/blob/v0.1.0-alpha/docs/verification.md) for revisions and scope.

Physical app QR import, USB/RF interoperability, installation, power-loss and
spare recovery, Pi 4 with 4 GB RAM, and an eight-hour rehearsal remain open.
The enrollment VM uses an empty channel catalog; it does not establish a fully
provisioned mesh. Coverage, RF latency and resource targets are not guarantees.

## Breaking prototype changes

Use `mish`, `services.mish` and `/var/lib/mish` in commands, configuration and
runtime paths. Earlier prototype names are replaced. The appliance runtime is
now Rust-native. The former read-only attendee-feed model is superseded by
community radio participation; announcement routes remain compatibility-only.

One coordinator remains authoritative, with manually activated spares.
Additional transports, replication and automatic failover are deferred.
